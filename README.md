# CatchTheTail — 꼬리잡기 파티게임

로봇 캐릭터들이 정해진 목표 색의 배터리 꼬리를 빼앗는 멀티플레이 파티게임입니다. 1분마다 색이 바뀌며, 경기 종료 시 보유 꼬리 수를 기준으로 승자를 정합니다.

> 프로젝트 자료를 통합한 기획·개발 기준 문서입니다. 실제 구현 완료를 의미하지 않습니다. 구체적인 `MoonParty_UE57_Code_Prompt_Info (1).md`의 확정 내용을 우선 반영하고, 제안 및 문서 간 차이는 별도로 표시했습니다.

## 핵심 게임 흐름

1. 플레이어가 방에 참가하고 경기를 시작합니다.
2. 참가자에게 서로 겹치지 않는 색을 무작위로 배정합니다.
3. 각 플레이어는 자신의 목표 색을 가진 상대의 꼬리 끝을 잡습니다.
4. 꼬리를 잡으면 자신의 꼬리 수가 늘고, 잡힌 상대의 꼬리 수는 줄어듭니다.
5. 잡힌 플레이어는 다음 라운드까지 유령 상태가 됩니다.
6. 1분마다 색을 다시 배정하고 유령을 부활시킵니다.
7. 전체 경기 시간이 끝나면 보유 꼬리 수를 비교합니다. 동점이면 연장전을 진행합니다.

## 게임 규칙

### 색상과 목표

| 순서 | 색 | HEX |
|---|---|---|
| 1 | 빨강 | `#E53935` |
| 2 | 주황 | `#FB8C00` |
| 3 | 노랑 | `#FDD835` |
| 4 | 초록 | `#43A047` |
| 5 | 하늘 | `#29B6F6` |
| 6 | 파랑 | `#2B3BFF` |
| 7 | 보라 | `#8E24AA` |
| 8 | 분홍 | `#FF4FA3` |

- 라운드마다 참가 인원만큼 색을 중복 없이 무작위 배정합니다.
- 직전 라운드와 같은 색은 가능한 경우 피하고, 불가능하면 허용합니다.
- 목표는 색상 순서상 다음 색이며, 분홍 다음은 빨강입니다. 자기 색은 제외합니다.
- UI는 색 이름과 도형 아이콘을 함께 표시합니다.
- **확인 필요:** 8명 미만일 때 실제 참가자에게 배정된 색만 순환하는 방식은 정보 시트 본문에서는 제안, 프롬프트 초안에서는 적용 규칙으로 적혀 있습니다. 예: 빨강·파랑·분홍 참가 시 빨강 → 파랑 → 분홍 → 빨강.

### 시간과 행동

- 전체 경기 시간: 방 설정으로 5~10분, 기본값 미정.
- 라운드 간격: 60초. 색 변경 5초 전부터 카운트다운.
- 잡기: 정해진 목표 꼬리만 획득 가능, 쿨타임 없음.
- 목표가 아닌 상대: 밀기 가능, 밀기 쿨타임 1초.
- 꼬리 획득 직후 무적 시간 없음.
- 목표 추격 중 이동 속도 1.2배.
- 잡기 거리 150cm, 밀기 거리 150cm, 밀기 힘 800은 **테스트용 제안값**이며 에디터에서 조절합니다.

### 유령과 부활

- 꼬리를 잡힌 플레이어는 유령(전자파) 상태가 됩니다.
- 유령 이동 속도는 기본의 0.5배입니다.
- 이동만 가능하며 점프·달리기·잡기·밀기는 사용할 수 없습니다.
- 벽을 통과할 수 없고 다른 플레이어와 충돌합니다.
- 다음 라운드 시작 시 유령이 마지막으로 있던 위치에서 부활합니다.

### 승리와 연장전

- 경기 종료 시 가장 많은 꼬리를 보유한 플레이어가 승리합니다.
- 동점이면 좁은 맵에서 긴 꼬리잡기 연장전을 진행합니다.
- 승점에 따라 꼬리가 길어지고, 상대 꼬리 끝을 먼저 잡으면 승리합니다.
- **확인 필요:** 자료의 ‘가장 많이 잡은 사람’과 ‘보유 꼬리 수’ 표현을 최종 점수 정의로 통일해야 합니다. 3명 이상 동점일 때 연장전 처리도 미정입니다.

## 입력과 이동 속도

| 입력 | 동작 | 구분 |
|---|---|---|
| WASD | 이동 | 제안 |
| 마우스 이동 | 카메라 회전 | 제안 |
| 마우스 좌클릭 | 잡기 / 왼손 | 확정 |
| 마우스 우클릭 | 밀기 / 오른손 | 확정 |
| Space | 점프, 공중 재점프 불가 | 확정 |
| Shift 유지 | 최대 3초 달리기, 이후 5초 쿨타임 | 현재 규칙, 변경 가능 |

속도 배율은 곱셈 대신 버프를 합산합니다.

```text
최종 이동 속도 = 기본 이동 속도 × (1.0 + 적용 중인 버프 합계)
달리기: 1.5배
목표 추격: 1.2배
달리기 + 목표 추격: 1.7배
유령: 0.5배 — 달리기와 추격 적용 불가
```

달리기는 현재 시간·쿨타임 방식과 검토 중인 게이지 방식을 교체하기 쉽게 구성하는 것이 제안되어 있습니다. 추격 버프의 정확한 발동 조건은 구현 전에 정해야 합니다.

## 캐릭터와 꼬리

- 둥근 블록·장난감 형태의 로봇, 단순한 LED 얼굴과 짧은 팔다리.
- 배터리 모듈을 연결해 꼬리를 표현하며, 꼬리 길이로 진행 상태를 보여줍니다.
- 기존 로봇 모델을 사용하고, 메시를 블루프린트에서 교체할 수 있게 합니다.
- 표정은 스프라이트 이미지 전환 방식으로 계획되어 있습니다.
- 구체적인 정보 시트는 **소켓 연결**을 원하는 표현으로 명시합니다.
- 초기 시스템 문서는 **이동 경로 기록 + Spline**을 제안합니다. 소켓 연결 외형과 이동 추종 방식을 어떻게 결합할지는 구현 전에 검증합니다.
- 꼬리 데이터와 시각 표현을 분리하고, 배터리마다 독립적인 복제 Actor를 만들지는 성능과 판정 요구에 따라 결정합니다.

## 코드 구조와 네트워크

| 클래스 | 역할 |
|---|---|
| `ACTCharacter` | 이동, 카메라, 점프, 달리기, 잡기·밀기 입력, 행동 몽타주 재생 |
| `UCTHUDWidget` / `UCTScoreEntryWidget` / `UCTResultWidget` | WBP 부모 클래스. 시간·라운드·카운트다운, 내 색·목표 색, 꼬리 수, 달리기·밀기 게이지, 점수판, 결과 화면 |
| `UCTAnimInstance` | 애니메이션 BP 부모. 이동 속도·공중·달리기·유령 상태를 AnimGraph 변수로 제공 |
| `ACTPlayerController` | 입력 매핑 등록, 개인 UI와 서버 요청 연결 |
| `ACTGameMode` | 서버의 입장 처리, 색 배정, 라운드와 승패 진행 |
| `ACTGameState` | 남은 시간, 라운드 번호, 경기 상태 공유 |
| `ACTPlayerState` | 플레이어 색, 목표 색, 꼬리 수·점수, 유령 상태 |
| `ECTColor` | 8색 열거형과 색상 테이블 |
| 꼬리 컴포넌트 / AI Controller | 후속 구현, 최종 클래스 이름 미정 |

- 서버가 색 배정, 잡기 성공, 점수, 라운드 전환, 유령 전환을 결정합니다.
- 클라이언트는 입력을 전달하고 복제된 상태를 표시합니다.
- 색·목표 색·꼬리 수·유령 여부·남은 시간·라운드 번호를 복제합니다.
- 잡기 요청은 대상 유효성, 거리, 꼬리 끝 위치, 색상, 상태, 중복 획득 여부를 서버에서 검증합니다.
- 이동은 `CharacterMovementComponent`를 기반으로 하고 속도 변경도 서버 기준으로 처리합니다.
- 일회성 효과와 게임의 지속 상태를 분리합니다.
- 설정값은 `UPROPERTY`로 노출하고, `.h` / `.cpp`를 분리하며 한국어 주석을 사용합니다.
- Enhanced Input 사용은 제안되어 있습니다.

예상 전체 경기 흐름:

```text
Lobby → Countdown → Playing → GameOver → Result
```

## 첫 구현 범위

- [ ] `CatchTheTail` 프로젝트와 기본 클래스 구성
- [ ] 이동·점프·달리기·3인칭 카메라
- [ ] 잡기·밀기 입력 연결
- [ ] 입장 처리와 색·목표 색 배정
- [ ] 남은 시간·라운드 번호·플레이어 상태 복제
- [ ] 바닥·벽·PlayerStart 8개를 갖춘 테스트 레벨
- [ ] Listen Server에서 2~3명 연결과 상태 동기화 확인

꼬리 연결, 유령 세부 동작, 연장전, UI, 애니메이션과 표정은 후속 단계입니다. 위 체크리스트는 완료 보고가 아닌 구현 계획입니다.

## 7주 개발 계획

| 주차 | 주요 작업 | 완료 기준 |
|---|---|---|
| 1주 | 프로젝트, 기본 이동·카메라·맵, 네트워크 | Host와 Client 접속 및 이동 동기화 |
| 2주 | 배터리·꼬리 데이터, 연결과 이동 추종 | 꼬리 추가·제거 및 추종 확인 |
| 3주 | 서버 잡기 판정, 색상·라운드·승리 규칙 | 멀티플레이 한 경기 진행 |
| 4주 | AI 탐색·추격·잡기·도주 | 플레이어와 AI의 핵심 꼬리 시스템 공유 |
| 5주 | 방 생성·참가, Ready, HUD, 결과 화면 | 로비 → 경기 → 결과 흐름 완성 |
| 6주 | 아트·애니메이션·VFX·SFX, 최적화 | 플레이 피드백 정리와 주요 버그 수정 |
| 7주 | 다인 QA, 연결 오류·재시작 검증, 패키징 | 최종 실행 빌드와 백업 |

AI 모드는 초기 기획의 후속 범위이며, 현재 기본 코드 요청에는 포함되지 않습니다. AI는 단순 상태 머신으로 시작하는 방향이 제안되어 있습니다.

## 우선순위와 검증

**P0:** 접속·스폰·이동, 꼬리 데이터와 판정, 획득·점수·승리, 기본 UI, 재시작.

**P1:** AI, 로비·Ready·카운트다운, 결과 화면, 캐릭터 색상, VFX·SFX.

**P2:** 스킨, 추가 맵·모드, 특수 능력, 랭킹·통계, 관전자·리플레이.

- [ ] 모든 참가자에게 색·꼬리·점수·유령 상태가 동일하게 보임
- [ ] 서버에서 잡기 조건을 검증하고 동시 요청의 중복 획득을 방지함
- [ ] 색 전환과 부활이 같은 라운드 기준으로 작동함
- [ ] 유령의 금지 행동과 충돌 규칙이 적용됨
- [ ] 이동 배율·달리기 시간·밀기 쿨타임이 규칙과 일치함
- [ ] 승리·동점·연장전·재시작 흐름을 확인함
- [ ] 접속·퇴장과 다인 플레이를 테스트함
- [ ] 색 이름·아이콘과 목표 표시를 쉽게 이해할 수 있음
- [ ] 패키징한 빌드에서 접속부터 경기 종료까지 확인함

## 남은 결정 사항

- 8명 미만의 목표 색 순환 규칙 최종 승인.
- 기본 경기 시간, 시작 꼬리 수, 0개일 때 처리 및 획득당 이동하는 배터리 수.
- 보유 꼬리 수와 누적 획득 수 중 최종 점수 기준.
- 꼬리 최대 길이·메시·연결 구조·추종 방식.
- 목표 추격 버프의 거리·방향 등 발동 조건.
- 잡기 거리·밀기 힘·기본 이동 속도의 테스트 결과.
- 달리기 방식, 맵 크기, 연장전 참가자·승점·종료 처리.
- 진행 중 참가·퇴장, 방장 종료, 최대 접속 수와 세션 구성.
- AI 수와 난이도, 연장전 및 유령 세부 구현 시점.
