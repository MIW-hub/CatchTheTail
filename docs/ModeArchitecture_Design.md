> 작성일: 2026-11-13 · 대상: 보물찾기 모드 추가를 위한 1번 작업 ("모드 구조 분리")
> 관련 문서: `docs/Mode_TreasureHunt_Plan.md` (규칙 확정 v6)
> 원칙: **꼬리잡기는 지금과 똑같이 동작해야 합니다.** 이번 작업에서는 새 규칙을 넣기 전에, 꼬리잡기를 "모드 하나"로 감싸는 데까지만 합니다.

## 1. 현재 구조 — 모드가 하나뿐이라 규칙이 곳곳에 박혀 있는 곳

> 아래는 코드를 읽어서 확인한 내용입니다(`CTGameMode.cpp` 702줄 중 시작, 종료, 라운드, 색 배정 부분 확인).

### 1-1. GameMode (`ACTGameMode`)가 하는 일
| 기능 | 위치 | 꼬리잡기 전용인가? |
|---|---|---|
| 경기 시작 `StartGame` | 플레이어 초기화(꼬리 수, 유령 해제, 색 초기화), 시간 정보 설정, `Playing` 단계로 | 반은 공통(시간, 단계), 반은 꼬리잡기 전용(색 초기화, 전화 쿨, 기권 해제) |
| AI 채우기 `SpawnAIPlayers` | 로비 설정 인원만큼 AI 생성 | 공통 (단, 보물찾기는 AI로 채우지 않음) |
| 경기 종료 `EndGame` | **꼬리 최다 플레이어를 승자로 계산**, 결과 저장, 로비 복귀 예약 | 승자 계산은 꼬리잡기 전용 |
| 라운드 시작 `StartNewRound` | 맵에 남은 꼬리 아이템 제거, 유령 부활, 꼬리 보충, **색과 목표 재배정**, 라운드 종료 시각 설정 | 대부분 꼬리잡기 전용 |
| 색 배정 `AssignColorsAndTargets` | 개인별 색 + 목표 색(서로 겹치지 않게) | 꼬리잡기 전용 |
| 흐름 타이머 `TickGameFlow` | 0.2초마다 "게임 시간 끝? 라운드 시간 끝?" 확인 | 구조는 공통, 의미는 모드마다 다름 |
| 꼬리 획득 `HandleTailGrabbed` / `FinalizeTailGrabbed` | 대결 후 **꼬리를 빼앗고 상대를 유령으로** 만듦 | 꼬리잡기 전용 |
| 기권 `HandleForfeit`, 유령 이동 `HandleGhostRelocate` | 유령·기권 처리 | 꼬리잡기 전용 |
| 입장/퇴장/복귀 (`PostLogin`, `Logout`, `HandleSeamlessTravelPlayer`, `ReturnToLobby`) | 접속 흐름 | 공통 |

### 1-2. GameState / PlayerState / 설정
- **GameState**: `Phase`, `RoundNumber`, `RoundEndServerTime`, `GameEndServerTime`, `Winners`, `bIsTie`, `MatchSettings`가 복제됩니다. 로비 시작 가능 판정 `CanStartLobby`가 "사람과 AI 합쳐 2명 이상, 모두 Ready"로 고정되어 있습니다.
- **PlayerState**: 색, 목표 색, 꼬리 수, 유령, 기권이 있습니다. 팀, 에너지(개인 점수), 라운드 승점 개념은 없습니다.
- **설정**: 방장이 로비에서 정한 `FCTMatchSettings`(경기 시간, 라운드 시간, 인원, 시작 꼬리, 전화 대기, 부쉬, AI 수)를 `GameInstance`에 저장했다가 경기 맵의 GameMode가 읽습니다. **모드 항목이 없습니다.**
- **UI**: HUD(목표 색 카드, 꼬리 수, 순위표), 결과 화면(꼬리 수 순위), 로비 플레이어 목록이 모두 꼬리잡기 기준입니다.
- **잡기**: `UCTGrappleComponent`가 대결을 진행한 뒤 GameMode의 `FinalizeTailGrabbed`를 부릅니다. AI(`ACTAIController`)도 목표 색 기준으로 움직입니다.

## 2. 제안 구조 — "규칙 객체" 방식

### 2-1. 핵심 아이디어
GameMode는 지금처럼 **하나(`ACTGameMode`)** 를 유지하고, 모드마다 다른 부분만 **규칙 객체(`UCTGameRule`)** 로 분리합니다.

```text
ACTGameMode (공통 흐름: 접속, 카운트다운, 시간 진행, AI 생성, 로비 복귀)
   └── UCTGameRule  ← 모드 선택(MatchSettings.Mode)에 따라 하나가 만들어짐
          ├── UCTRule_TailChase    (지금 코드를 그대로 옮김)
          └── UCTRule_TreasureHunt (새로 만듦)
```

**이 방식을 고른 이유**
- 접속, 로비 복귀, AI, 카운트다운 같은 공통 부분을 모드마다 복사하지 않아도 됩니다.
- 다른 방법인 "모드마다 별도의 GameMode 클래스"는 공통 흐름을 두 벌 관리하게 되고, 로비에서 모드를 바꿀 때 이동할 GameMode를 바꾸는 작업도 필요해서 이번 규모에는 과합니다.
- 모드를 더 늘릴 때(팀전 변형, 풋볼) 규칙 객체만 추가하면 됩니다.

### 2-2. 규칙 객체가 맡는 일 (인터페이스 초안)
| 함수 | 부르는 때 | 꼬리잡기 | 보물찾기 |
|---|---|---|---|
| `OnMatchStart()` | 경기 시작 | 꼬리 수·색 초기화 | 팀 확정, 에너지 초기화, 라운드 승점 0 |
| `OnRoundStart(n)` | 라운드 시작 | 색·목표 재배정, 유령 부활 | 에너지 100개 + 오브젝트 20개 배치, 무작위 스폰, 개인 에너지 0 |
| `OnRoundTimeUp()` | 라운드 시간 종료 | 다음 라운드 시작 | 팀 에너지 비교, 승점, 3라운드면 경기 종료 |
| `OnGameTimeUp()` | 전체 시간 종료 | 승자 계산 후 종료 | 사용 안 함(라운드 수로 끝남) |
| `HandleGrab(grabber, victim)` | 꼬리잡기 성공 | 대결 → 꼬리 빼앗기 → 유령 | 2초 정지만, 빼앗지 않음 |
| `ComputeResult()` | 경기 끝 | 꼬리 최다 | 라운드 승점, 무승부 |
| `GetStartRequirements()` | 로비 시작 가능 판정 | 사람+AI 2명 이상, 모두 Ready | 양 팀 각 1명 이상, 모두 Ready |
| `UsesGhost()`, `UsesTargetColor()`, `UsesTeams()` | 판단용 | 유령 O, 목표 색 O, 팀 X | 유령 X, 목표 색 X, 팀 O |
| `PickSpawnTransform(player)` | 스폰 | 기존 PlayerStart | 무작위 안전 스폰(8m 규칙) |

### 2-3. 복제되는 정보 (클라이언트 화면용)
| 위치 | 추가 항목 |
|---|---|
| `FCTMatchSettings` | `Mode`(꼬리잡기/보물찾기) — 로비 설정에 새 항목으로 추가, 기본값 꼬리잡기 |
| `ACTGameState` | `ModeType`, 팀 색 두 개, 팀별 라운드 승점, 팀별 에너지(자기 팀만 보이게 처리) |
| `ACTPlayerState` | `TeamId`, 개인 에너지, 개인 누적 에너지(결과 점수) |

> 상대 팀 에너지가 클라이언트에 복제되지 않게 하는 처리는 보물찾기 단계(2주차)에서 합니다. 지금 구조 분리 단계에서는 필드만 준비합니다.

### 2-4. UI는 "모드에 따라 보이는 패널이 바뀌는" 방식
- HUD: 꼬리잡기 패널(목표 색 카드, 꼬리 수) 그룹과 보물찾기 패널(라운드 승점, 팀 에너지, 내 에너지) 그룹을 나눠 두고 `ModeType`에 따라 켜고 끕니다. **기존 HUD의 위치와 크기는 건드리지 않습니다**(이전에 직접 조정한 값 보존).
- 결과 화면과 방 전적: 모드별 제목과 표 형식을 바꿉니다.
- 로비: 모드 선택 항목 추가, 팀전일 때만 레드/블루 패널과 팀 변경 UI를 보여줍니다.

## 3. 이행 순서 (1주차, 꼬리잡기가 안 깨지는 순서)

각 단계가 끝날 때마다 **빌드와 꼬리잡기 한 판 확인**을 합니다. 확인이 실패하면 그 단계에서 멈추고 고칩니다.

| 단계 | 작업 | 위험 | 예상 |
|---|---|---|---|
| 0 | **기준선 기록**: 지금 꼬리잡기 한 판의 로그와 결과(라운드 시작 로그, 색 배정, 잡기, 종료)를 저장해 비교 기준으로 사용 | 없음 | 0.5일 |
| 1 | **모드 설정 항목 추가**: `FCTMatchSettings`에 `Mode`(기본 꼬리잡기), 로비 경기 설정에 모드 선택 추가. 보물찾기를 고르면 아직 "준비 중"으로 막아 둠 | 낮음 (설정 저장, 로비 UI) | 1일 |
| 2 | **규칙 객체 껍데기**: `UCTGameRule` 베이스와 `UCTRule_TailChase`를 만들고, GameMode가 규칙 객체를 만들어 함수만 **그대로 위임**(코드 이동 없이 호출만 연결) | 중간 (호출 순서) | 1일 |
| 3 | **코드 옮기기**: 색 배정, 라운드 보충, 승자 계산, 잡기 처리를 `UCTRule_TailChase`로 한 덩어리씩 옮기고 매번 확인 | 중간 | 1.5일 |
| 4 | **복제 필드 추가**: GameState/PlayerState에 `ModeType`, `TeamId`, 에너지 필드 준비 (값은 아직 안 씀) | 낮음 | 0.5일 |
| 5 | **UI 모드 분기 틀**: HUD, 결과, 로비에 모드에 따른 켜고 끄기 틀 (꼬리잡기는 변화 없음) | 낮음 | 1일 |
| 6 | **회귀 확인**: AI 포함, 2명과 8명, 기권, 유령, 꼬리 대결, 결과, 로비 복귀, 방 전적, 패키징 | — | 1일 |

합계 약 **6~7일** (앞서 문서에 적은 모드 구조 분리 3~4일보다 늘었습니다. 꼬리잡기가 깨지지 않는지 확인하는 작업을 단계마다 넣었기 때문입니다).

### 일정 반영
- 앞서 제안한 1주차(11/13~11/19)에 단계 0~3까지, 4~6은 2주차 초반(11/20~11/22)에 합니다.
- 보물찾기 규칙(에너지, 라운드, 스폰)은 단계 3이 끝난 뒤 시작합니다. 팀 음성 프로토타입은 이 기간에 병행해서 가능 여부만 먼저 확인합니다.

## 6. 위험과 결정 사항

| 항목 | 내용 | 대응 |
|---|---|---|
| 회귀 | 코드 이동 중 꼬리잡기가 미묘하게 달라질 수 있음 | 단계 0의 기준선과 단계마다 한 판 비교 |
| 네트워크 | 규칙 객체는 서버에서만 존재, 클라이언트는 GameState 복제값만 봄 | 규칙 객체를 복제하지 않고, 화면에 필요한 값만 GameState/PlayerState로 |
| 설정 저장 | 새 `Mode` 항목이 이전 저장값과 어긋날 수 있음 | 기본값(꼬리잡기)으로 읽고, 항목이 없으면 기본값 |
| 로비 UI | 경기 설정 항목이 늘어 패널이 넘칠 수 있음 | 기존 패널에 한 줄 추가하고 넘치면 스크롤 |
| AI | 보물찾기에서는 AI를 채우지 않기로 했지만 꼬리잡기는 그대로 | 규칙 객체의 "AI 허용" 값으로 구분 |

### 3단계 이후에도 GameMode에 남아 있는 꼬리잡기 전용 코드 (다음 단계에서 훅으로 뺄 후보)
| 함수 | 내용 | 보물찾기에서 |
|---|---|---|
| `HandlePlayerLeftDuringGame` | 이탈 시 목표 색 재연결 | 팀 인원 변화 처리로 교체 |
| `HandleForfeit` | 기권(꼬리 0, 순위 제외, 유령) | 기권 규칙 별도 결정 필요 |
| `HandleGhostRelocate` | 유령 이동(F) | 유령이 없어서 사용 안 함 |
| `RefreshAllChaseBuffs` | 목표 추격 속도 버프 | 목표 색이 없어서 사용 안 함 |

### 4단계에서 정한 복제 원칙 (보물찾기용)
- **개인 에너지는 본인에게만** 보냅니다(`COND_OwnerOnly`). 상대 팀 에너지를 클라이언트가 알 수 없어야 하기 때문입니다.
- **우리 팀 합산 에너지**는 아직 필드가 없습니다. 팀원에게만 보내야 해서 2주차(보물찾기 구현)에서 팀 단위 복제 조건으로 추가합니다.
- 결과 화면의 개인 점수는 **경기가 끝난 뒤 `ResultEnergy`로 공개**합니다.
